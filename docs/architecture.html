System architecture

Presentation — Vue 3 SPA (Vite dev server, port 3030)

App.vue is the shell: sidebar navigation, global FilterBar, profile and task modals, and a <router-view> for the active page.

Shared client state — composables (singleton refs)

Module-scoped ref()s declared outside the exported function, so every component that calls the composable shares one instance of the state.

useFilters.js — period / location / category / status useI18n.js — en + ja, locale drives currency useAuth.js — mock user and tasks

API client — client/src/api.js

The single place the backend host is defined (API_BASE_URL). Every component goes through it; no component calls axios directly. Filters are serialised to query params here, and any value equal to 'all' is dropped rather than sent.

axios http://localhost:8090/api
↓ HTTP / JSON ↓

Application — FastAPI (uvicorn, port 8090)

server/main.py holds routes, Pydantic response models and the filtering helpers. CORS is wide open (allow_origins=["*"]) because it is a local demo.

apply_filters() — warehouse / category / status filter_by_month() — month or Q1..Q4 2025 Pydantic response models aggregation for /dashboard and /reports
↓

Data — server/mock_data.py + server/data/*.json

Every JSON file is read once at import time into module-level Python lists and dicts. There is no database and no persistence: filtering happens in Python over in-memory lists, and a server restart resets everything to the file contents.

Tech stack

Frontend
  • Vue 3.4 — Composition API in newer views, Options API still in Reports.vue
  • Vue Router 4 — HTML5 history mode, 6 routes
  • Vite 5 — dev server and build, port set in vite.config.js
  • axios 1.6 — the only HTTP client
  • Charts are hand-written SVG and CSS, no charting library
  • Styling is plain scoped CSS, no framework
Backend
  • Python + FastAPI — single module main.py
  • Pydantic — request and response validation
  • uvicorn — ASGI server
  • uv — dependency management (uv run python main.py)
  • pytest + FastAPI TestClient — tests in tests/backend/
  • No ORM, no database driver, no cache

Data flow — a filtered dashboard load

  1. User changes a dropdown in FilterBar, which writes to the shared refs in useFilters.
  2. The active view watches those refs and calls getCurrentFilters(), mapping period to month and location to warehouse.
  3. The view calls api.getDashboardSummary(filters); api.js builds the query string and drops every 'all' value.
  4. axios issues GET http://localhost:8090/api/dashboard/summary?....
  5. FastAPI runs apply_filters() then filter_by_month() over the in-memory lists and aggregates the totals.
  6. Pydantic validates the response shape and FastAPI serialises it to JSON.
  7. The view assigns the payload to its refs; computed properties derive the KPIs, tables and SVG charts, and Vue re-renders.

Domain model

Dimensions used by the filters
  • Warehouse: London, San Francisco, Tokyo
  • Category: Actuators, Circuit Boards, Controllers, Power Supplies, Sensors
  • Order status: Processing, Shipped, Delivered, Backordered
  • Period: 2025-01 through 2025-12, or Q1..Q4-2025
Entities
  • InventoryItem — sku, warehouse, category, quantity_on_hand, reorder_point, unit_cost
  • Order — order_number, customer, items[], status, order_date, total_value
  • DemandForecast — current vs forecasted demand, trend
  • BacklogItem — quantity needed vs available, days_delayed, priority
  • PurchaseOrder — supplier, quantity, expected delivery, linked to a backlog item

Key patterns

  • Single host definition. API_BASE_URL in api.js is the only place the backend origin appears in client code, so a port change is a one-line edit.
  • Singleton composables. Filter, locale and auth state live in refs declared at module scope, giving shared global state without a store library.
  • Server-side filtering. Filters are query params, not client-side array work, so every view refetches instead of slicing a cached list.
  • Raw refs, derived computed. Responses land in refs; KPIs, chart series and table rows are computed properties over them.
  • Aggregation lives in the backend. /dashboard/summary and both /reports/* endpoints compute quarters, revenue and fulfillment rate server-side from the raw orders list.

Observations

  • gap api.js exposes getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, but server/main.py defines no /api/tasks or /api/purchase-orders routes. App.vue calls the task methods, so those requests 404 at runtime.
  • gap views/Backlog.vue exists but is not registered in the router in main.js; the backlog table is rendered inside Dashboard.vue instead.
  • note purchase_orders.json is an empty list, so has_purchase_order on every backlog item is always false.
  • note /api/inventory accepts no month filter — inventory rows have no time dimension, only last_updated.
  • note Reports.vue is the last Options API view and reimplements number formatting by hand instead of using toLocaleString.
  • note Quarter boundaries are hardcoded to 2025 in both QUARTER_MAP and /api/reports/quarterly.
